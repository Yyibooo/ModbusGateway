## 2. 项目范围

最终完成一个 TCP–RTU 请求转发网关：网络客户端发起 Modbus 请求，网关经串口访问 RTU 设备，再把结果回复给原客户端。

第一版范围：

- 一个 TCP 监听端口、多个客户端连接。
- 一条 RTU 总线，支持根据请求中的 Unit ID 访问从站。
- 重点验证 0x03 读保持寄存器、0x06 写单个寄存器；0x10 写多个寄存器作为后续扩展。
- 有界请求队列、一个独占后端通信上下文的工作线程。
- 配置、日志、超时、队满处理、断连处理、正常退出。
- 可复现的功能测试、异常测试和简单性能记录。

初期不安排界面、云平台、MQTT、数据库、多进程、共享内存及复杂线程池。先完成上面的范围，后续按实际需要增加。

### 最终的数据流

```text
客户端 A → 连接线程 A ─┐
客户端 B → 连接线程 B ─┼→ 有界请求队列 → 后端工作线程 → RTU 总线 → 设备
客户端 C → 连接线程 C ─┘                      │
                                    结果回复原客户端
```

同一条 RTU 总线上的请求依次执行。多个网络客户端可以同时接入和排队。

前期把 RTU 后端暂时替换成 TCP 模拟设备，先验证网关调度，再接串口。

## 7. 单元 01：现在就能开始的任务

### 目标

自己编写项目根目录下的 `echo_server.c`，完成一个 TCP 连通实验。预计约 50～100 行，代码行数不作为验收条件。

### 程序行为

1. 创建 TCP socket，监听 `127.0.0.1:1502`。
2. 接受一个客户端连接。
3. 接收一段字节，打印实际收到的字节数和内容。
4. 发送固定两个字节 `OK`，不把 C 字符串结尾的 `\0` 计入回复长度。
5. 关闭客户端描述符和监听描述符，结束程序。
6. 先保留创建、绑定、监听、接受连接和接收的基本判断，并正常关闭有效描述符；发送循环等处理放到后续单元逐步补齐。

本单元只是连通实验，接收的这一段字节不被当作完整 Modbus 报文，也不承诺等于客户端的一次发送；单元 02 再处理完整消息的收发。

### 先画出流程，再写代码

## 8. 按需阅读的参考资料

- [libmodbus 官方函数文档](https://libmodbus.org/reference/)：查当前用到的函数和返回值，不必从头通读。
- [官方测试与示例目录](https://github.com/stephane/libmodbus/tree/master/tests)：先看 random-test-client/server，再按需看 unit-test 和 proxy-test。
- [modbus_proxy 官方说明和 TCP–RTU 示例](https://libmodbus.org/reference/modbus_proxy/)：单线程转发阶段使用。
- [libmodbus 版本记录](https://github.com/stephane/libmodbus/blob/master/NEWS.md)：确认 modbus_proxy 的版本要求。
- [mbusd](https://github.com/3cky/mbusd)：已有 TCP–RTU 网关，后期参考配置、错误处理和部署。
- [Modbus 官方协议资料入口](https://www.modbus.org/modbus-specifications)：需要理解某个字段或功能码时再查。

先读懂当前小程序，再向完整项目扩展。每次学到的知识，都应该能对应到自己代码中的一个具体行为。
